# Stashly Broker Server

The Stashly Broker is an always-on relay, authentication, and metadata directory service for the Stashly decentralized mobile cloud system. It coordinates connections between mobile storage nodes (Android devices) and consumers (web applications, Windows mapped drives, and external clients). 

The broker operates on a zero-knowledge trust model: it manages access tokens, routes WebSocket data requests, stores encrypted file metadata, and caches ciphertexts on disk, but never possesses decryption keys or unencrypted file contents.

---

## Technical Specifications

- **Runtime**: Node.js (v18.x or v20.x recommended)
- **Language**: TypeScript (ES2022 target)
- **HTTP Server**: Express 4.x
- **WebSocket Protocol**: `ws` 8.x
- **Database & ORM**: PostgreSQL with Prisma ORM 5.x
- **Authentication**: JSON Web Tokens (`jsonwebtoken`) with `bcryptjs` password hashing
- **Environment Management**: `dotenv`

---

## Database Schema and Architecture

The broker uses PostgreSQL with Prisma ORM (`prisma/schema.prisma`). The relational schema enforces cascade rules to guarantee that unpairing nodes or revoking users cleanly purges metadata and cache files.

### Core Data Models

1. **`User`**:
   - Stores account credentials (`id`, `email`, `passwordHash`, `createdAt`).
   - Maintains relationships with paired devices (`userDevices`) and issued pairing tokens (`pairingTokens`).

2. **`Device`**:
   - Represents a physical Android storage node (`id`, `name`, `platform`, `osVersion`, `appVersion`, `status`, `storageQuotaMb`, `lastSeenAt`, `createdAt`).
   - Status is actively set to `online` or `offline` based on live WebSocket connection state.

3. **`UserDevice`**:
   - Represents a multi-tenant permission link between a `User` and a `Device`.
   - Fields:
     - `role`: Role of the connection (`owner` or `viewer`).
     - `scopeMode`: Access permission boundary (`ALL`, `CUSTOM_FOLDER`, `CUSTOM_FILE`, `NONE`).
     - `scopePath`: Path restriction string (e.g., `/DCIM/Camera` or `/Documents/tax.pdf`).
     - `scopeName`: Friendly display name for the scope.
     - `sharingEnabled`: Boolean toggle to pause/resume data serving for this specific client.

4. **`FileEntry`**:
   - Stores encrypted file metadata cataloged from the mobile device.
   - Fields: `id`, `deviceId`, `path`, `name`, `sizeBytes`, `contentHash`, `mimeType`, `encryptedDek`, `isCached`, `cacheKey`, `cachedAt`, `lastAccessAt`.
   - The `encryptedDek` contains the AES-256-GCM wrapped data key as generated by the phone's hardware master key.

5. **`PairingToken`**:
   - Short-lived, single-use 8-character pairing tokens generated for pairing handshakes.
   - Automatically invalidated upon redemption (`used: true`) or expiration (`expiresAt`).

## WebSocket Relay and DeviceHub Architecture

The real-time communication pipeline between the broker and mobile devices is managed by `DeviceHub` (`src/ws/deviceHub.ts`):

1. **Connection Upgrade**:
   - Mobile devices connect to `GET /ws/device?token=<deviceJwt>`.
   - `src/ws/server.ts` validates the JWT token, extracts the `deviceId`, and upgrades the HTTP connection to a WebSocket.
   - `DeviceHub.registerConnection()` updates the database device status to `online` and binds event listeners.

2. **Correlation-ID Request Routing**:
   - When a client requests a file download (`GET /files/:id/download`), the broker generates a UUID `requestId` and stores a pending Promise in memory with a 15-second timeout (`DEVICE_FETCH_TIMEOUT_MS`).
   - The broker sends `{ type: "fetch_request", requestId, path }` to the phone over WebSocket.
   - The phone reads the encrypted data and replies with `{ type: "fetch_result", requestId, ok: true, dataBase64 }`.
   - The pending Promise resolves with the binary Buffer, writes a copy to the local cache (`storage/cache/<fileId>.bin`), and streams the ciphertext to the client.

3. **Presence and Push Telemetry**:
   - When web clients interact with the dashboard, heartbeats are sent to `/devices/presence`.
   - `DeviceHub` routes real-time client status to the phone via `client_presence` messages, allowing the mobile app to display active client indicators.
   - If a node is removed or unlinked from the web dashboard, `DeviceHub.notifyDeviceRemoved()` sends a `node_unlinked` event before closing the socket with code `4004`.

## REST API Reference

### Authentication Routes (`/auth`)

- **`POST /auth/register`**: Register a new user account.
  - Body: `{ "email": "string", "password": "string" }`
  - Response: `201 Created` with `{ "token": "jwt_string" }`
- **`POST /auth/login`**: Authenticate an existing user.
  - Body: `{ "email": "string", "password": "string" }`
  - Response: `200 OK` with `{ "token": "jwt_string" }`

### Device Management Routes (`/devices`)

- **`GET /info`**: System network discovery and auto-detected LAN IP.
  - Response: `200 OK` with `{ "service": "stashly-broker", "suggestedBrokerUrl": "string", "localIp": "string" }`
- **`POST /devices/pairing-tokens`** *(Requires User Auth)*: Generate single-use pairing code.
  - Response: `201 Created` with `{ "token": "8_CHAR_CODE", "expiresAt": "ISO_TIMESTAMP" }`
- **`POST /devices/pair`**: Redeem pairing token from Android node.
  - Body: `{ "token": "string", "deviceName": "string", "platform": "android", "osVersion": "string", "appVersion": "string" }`
  - Response: `201 Created` with `{ "deviceId": "string", "deviceToken": "string", "userId": "string", "userEmail": "string" }`
- **`GET /devices`** *(Requires User Auth)*: List paired storage nodes with live presence and client scopes.
- **`PATCH /devices/:id`** *(Requires User Auth)*: Rename a storage node.
- **`DELETE /devices/:id`** *(Requires User Auth)*: Remove user access to a node. If no users remain, the device and all associated file entries are deleted.
- **`POST /devices/presence`** / **`DELETE /devices/presence`** *(Requires User Auth)*: Toggle web client live presence.
- **`GET /devices/self`** *(Requires Device Auth)*: Node self-query to inspect active connections and scopes.
- **`PUT /devices/self/scope`** *(Requires Device Auth)*: Update access scope for a connected client.
- **`PUT /devices/self/client/:targetUserId/sharing`** *(Requires Device Auth)*: Toggle sharing enabled/disabled for a client.
- **`DELETE /devices/self/client/:targetUserId`** *(Requires Device Auth)*: Disconnect and unlink a specific client.
- **`DELETE /devices/self/reset`** *(Requires Device Auth)*: Perform complete node reset and delete database records.

### File Metadata and Download Routes (`/files`)

- **`GET /files?deviceId=<optional>`** *(Requires User Auth)*: Query file metadata matching the client's assigned scope.
- **`GET /files/:id/download`** *(Requires User Auth)*: Download ciphertext.
  - Headers Returned:
    - `Content-Type: application/octet-stream`
    - `X-Encrypted-Dek: <base64_wrapped_dek>`
    - `X-From-Local-Cache: true|false`

## Access Control Engine (`src/access.ts`)

Access enforcement is validated on every metadata query and file download request:

1. **`isPathAllowed(filePath, accessLink)`**:
   - If `sharingEnabled` is `false` or `scopeMode` is `"NONE"`, returns `false`.
   - If `scopeMode` is `"ALL"` or `scopePath` is empty, returns `true`.
   - If `scopeMode` is `"CUSTOM_FILE"`, requires exact normalized path equality.
   - If `scopeMode` is `"CUSTOM_FOLDER"`, requires normalized path prefix matching (`scopePath/`).

## Setup and Deployment

### Environment Configuration (`.env`)

```ini
PORT=4000
NODE_ENV=production
DATABASE_URL="postgresql://postgres:password@localhost:5432/stashly?schema=public"
JWT_SECRET="generate-a-secure-random-secret-key"
JWT_EXPIRES_IN="7d"
PAIRING_TOKEN_TTL_SECONDS=300
DEVICE_FETCH_TIMEOUT_MS=15000
STORAGE_DIR="./storage/cache"
```

### Installation and Database Migration

```bash
npm install
npm run prisma:migrate
npm run build
npm start
```
